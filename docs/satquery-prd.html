01

Problem, users, and scope boundary

An ISRO analyst holding a Cartosat-2S scene, a RISAT/EOS-04 SAR scene, or a bi-temporal pair currently reaches for a GIS desktop and a trained eye. The question they actually want to ask is a sentence: “what changed here between these two dates?”, “is there standing water under this cloud-free optical patch?”, “how many buildings in the north-east quadrant?”

Generic VLMs answer these badly. They hallucinate on nadir-view imagery, cannot read a 13-band uint16 GeoTIFF, produce nothing meaningful on SAR backscatter, and — critically for evaluation — give no account of how they arrived at an answer.

SatQuery AI is a task-routing agent over a registry of remote-sensing-adapted models, with a validation gate on the front and a structured execution trace on the back.

Primary user scenarios

Non-goals

Explicitly out of scope for the finale build. Each of these is a defensible cut, and saying so up front is cheaper than discovering it at hour 30.

  • Pixel-level segmentation masks from the VLM. Bounding-box grounding satisfies the PS. GeoPixel-class mask decoders add a SAM-2 dependency for marginal credit.
  • Training any model during the 36 hours. Adaptation is pre-work.
  • Multi-temporal sequences beyond two images. The PS requires bi-temporal.
  • On-the-fly orthorectification or co-registration. The hidden set is stated as pre-georeferenced and co-registered. We verify co-registration; we do not perform it. A misaligned pair produces a warning, not a silent resample.
  • User accounts, persistence, multi-tenancy. Single-session web app.
  • Beating SOTA on any benchmark. We report honest numbers on a fixed eval subset.

Requirements

DR-1

Mirror SECOND before anything else

Download the SECOND archive and store a second copy outside Google Drive (institutional drive, S3, a physical disk). Google Drive links to research datasets go quota-limited or dead without warning, and CDVQA is a mandatory evaluation dataset with no substitute.

AcceptanceSECOND extracted locally, image filenames cross-checked against Test_images.json from the CDVQA repo, with a documented match rate ≥ 95%.
DR-2

Build a BigEarthNet training subset, not the full archive

110 GiB will not fit in a Colab or Kaggle session and does not need to. Sample 20,000–40,000 co-located S1/S2 patch pairs, stratified across the 19 CORINE classes, using the official geographic split so train/test spatial correlation stays low. Filter out snow/cloud/shadow patches using the provided parquet metadata.

Package the subset as a Kaggle Dataset (or HF dataset repo) so training sessions mount it instead of re-downloading.

AcceptanceA <15 GB subset artifact, class histogram documented, loading in a fresh Kaggle notebook in under 3 minutes.
DR-3

Acquire genuine Cartosat-2S and EOS-04 scenes as test fixtures

The hidden evaluation set is Cartosat-2S optical and RISAT SAR. Benchmark datasets are 256²–512² PNG-like tiles; a real Cartosat-2S scene is a large multi-band GeoTIFF with its own band ordering, dtype, nodata convention, and scene geometry. Every preprocessing assumption learned on BigEarthNet needs testing against a real scene.

AcceptanceAt least one Cartosat-2S optical scene and one EOS-04 SAR scene downloaded from Bhoonidhi, opening cleanly through the ingest path, with band count, dtype, CRS, and GSD recorded in the fixture registry.
License note for the submission. VRSBench is CC-BY-NC-4.0 and Qwen2.5-VL-3B carries the Qwen Research License — both non-commercial. That is fine for a hackathon and for research evaluation, but state it explicitly in the submission so nobody claims a commercially deployable system. BigEarthNet (CDLA-Permissive), RSVQA (CC-BY-4.0), and CDVQA (Apache-2.0) are unrestricted. SECOND states no license at all — cite the paper and treat it as research-use.

Model registry requirements

Verdict

Do not run three 7B models. On a single 16 GB GPU you cannot hold GeoChat-7B, TEOChat-7B, and a change detector resident at once, and lazy load/unload at 15–30 s per swap will destroy the live demo.

Pick one VLM backbone and make everything else a small specialist. The recommended configuration is a 3B RS-adapted VLM as the single language-vision engine, plus two lightweight CNN/ViT specialists that produce structured facts the VLM verbalizes.

MR-1

Single resident VLM, specialists on demand

The VLM stays loaded for the process lifetime. Specialists are <1 GB and can all be co-resident. Total steady-state VRAM budget: ≤ 10 GB, leaving headroom on a 16 GB card and fitting a 12 GB card in 4-bit.

AcceptancePeak VRAM measured under a US-5 cross-modal query stays under budget; no model load occurs after warmup.
MR-2

Compositional change analysis, not monolithic change-VLM

Requirement #3 is satisfied by: siamese CD head → binary/semantic change mask → structured change statistics (changed area %, per-class from/to transitions, largest connected components with their bounds) → VLM verbalizes those facts into a change description or change-VQA answer.

This is more robust than TEOChat under time pressure, it produces a spatial output for the fusion requirement, and every intermediate is a trace-able artifact. TEOChat remains a registry entry to enable if time allows — it is the stronger scientific answer, but it carries a Video-LLaVA dependency stack pinned to older transformers, which is a real integration cost.

AcceptanceCDVQA test split scored end-to-end through the compositional path, with per-question-type accuracy reported.
MR-3

Registry entries are declarative and versioned

Every capability is a registry record, not a code branch. Selection reads the registry; adding a model is a config change.

04

Remote-sensing adaptation (PS requirement #1)

Verdict

The requirement says “at least one visual/VLM component must be fine-tuned on BigEarthNet or other open remote-sensing training data.” A fine-tuned visual component satisfies it. That is the insurance policy, and it is a few GPU-hours of well-trodden supervised learning — not a VLM fine-tune, which you have never done.

Run Track A to completion first. Only then attempt Track B.

AR-1

Track A — dual-branch S1+S2 encoder Required

Fine-tune a ViT-S or ResNet-50 for 19-class CORINE multi-label classification on the BigEarthNet v2.0 subset, with 12-channel input: 10 Sentinel-2 bands concatenated with 2 Sentinel-1 bands (VV, VH). Initialise from ImageNet weights, inflating the input stem to 12 channels.

This is the single highest-leverage run in the project. BigEarthNet is the only large public archive of co-registered optical and SAR pairs — which is precisely why the problem statement names it alongside a Cartosat/RISAT evaluation set. One training run therefore delivers:

  • PS requirement #1 — a visual component fine-tuned on BigEarthNet
  • PS requirement #4 — a genuine optical–SAR cross-modal component, rather than two independent predictions stapled together
  • A registry specialist that grounds the VLM's land-cover claims

Budget: 2–4 GPU-hours on a free T4 or P100 for 30k patches × ~10 epochs at 120×120. Kaggle is the recommended host — 30 GPU-hours/week, 12-hour sessions, and datasets mount without re-downloading. Colab free sessions get reclaimed mid-run.

AcceptanceMacro mAP reported on the official BigEarthNet v2.0 geographic test split, for three configurations: S2-only, S1-only, and fused. The fused number must beat both single-modality baselines — that ablation is the evidence for requirement #4.
AR-2

Track B — LoRA on the RS-VLM Target

LoRA-adapt AdaptLLM/remote-sensing-Qwen2.5-VL-3B-Instruct so the language model speaks in the vocabulary of your pipeline and answers in the answer-space the benchmarks expect.

Training data — roughly 12–15k instruction samples, mixed:

  • BigEarthNet-derived QA (~6k), template-generated from the 19-class labels and patch metadata: presence questions, dominant-cover questions, and explicitly SAR-referencing questions (“does the radar response indicate open water?”)
  • RSVQA-LR train split (~4k), to match benchmark answer formatting
  • VRSBench caption + referring (~3k), for the second single-image capability
  • Change-summary verbalization (~1k), teaching the model to convert structured change statistics into fluent descriptions

Config: LoRA rank 16, alpha 32, on attention and MLP projections; vision tower frozen; 4-bit base; gradient checkpointing; 1 epoch. Reported VRAM for Qwen2.5-VL-3B LoRA under LLaMA-Factory is ≈8.9 GB, which fits a free 16 GB T4 with headroom.

Budget: 6–10 GPU-hours. Use LLaMA-Factory or Unsloth rather than writing a training loop — for a first VLM fine-tune, a config file is the difference between shipping and debugging collator shapes at 3 a.m.

AcceptanceRSVQA-LR test accuracy for the adapted model beats the un-adapted base by a reported margin on a fixed 500-question subset. If it does not, ship Track A and report the negative result honestly — a documented failed ablation reads far better than a vague claim.
Hard constraint. Both tracks complete before the finale and ship as frozen checkpoints committed to the repo or an HF model repo. Fine-tuning inside a 36-hour window, with no prior VLM fine-tuning experience, is the single most reliable way to arrive at hour 30 with nothing running.
05

Agentic orchestration (PS requirement #5)

Design principle

The problem statement says only the observable execution trace is evaluated — internal reasoning text is not. That has a direct architectural consequence: the LLM classifies, a deterministic resolver decides.

If an LLM freely picks tools, the trace records an unreproducible choice. If a rule engine picks tools from typed registry predicates, the trace records a rule ID, the candidates considered, and why each was rejected. The second is auditable; the first is a transcript.

Graph topology

ingestOpen every uploaded file with rasterio. Emit a per-image manifest: sha256, driver, CRS, affine transform, shape, dtype, band count, nodata, GSD, footprint polygon, and inferred modality.
validateRun the typed check suite (VR-1 below). Every check emits name, status, expected, actual — passing checks are logged too, because a trace that only records failures proves nothing.
└─ conditional → reject if any check is FATAL · returns a named reason, never a crash
classifyLLM with structured output (Pydantic / JSON schema) maps the query to a task enum — vqa, caption, grounding, change_describe, change_vqa, cross_modal — plus extracted parameters and a self-reported confidence with alternatives.
└─ conditional → clarify if top-1 confidence < threshold or image count contradicts the task
planDeterministic resolver. Filters the registry on capability ∩ modality ∩ image_count ∩ input_spec, ranks survivors by declared eval score, and records the full candidate set with rejection reasons.
└─ conditional → degrade to a declared fallback if no candidate matches · e.g. SAR missing → optical-only path, flagged
preprocessPer-model input adaptation: band selection, dB conversion and percentile stretch for SAR, tiling for oversized scenes, resampling. Records every transform applied — this is where silent quality loss happens, so it must be visible.
executeRuns selected tools. Independent tools fan out in parallel. Each step records tool ID, version, resolved params, device, wall-clock ms, and a reference to the raw output.
fuseMerges text and spatial outputs into one answer payload: prose answer, geometry (boxes/masks in both pixel and geographic coordinates), and supporting evidence naming which model contributed which claim.
confidenceComposite score from named components (CF-1) — never a single opaque number.
respondAssembles the answer plus the complete trace document and streams it to the client.
OR-1

Trace is accumulated state, not logging

The trace is a first-class field on the LangGraph state with an append reducer, so every node contributes without any node owning the whole document. Logging is a side effect that can be lost; state is what the graph returns.

class TraceEntry(BaseModel):
    seq:        int
    node:       str
    started_at: datetime
    duration_ms:float
    status:     Literal["ok", "warn", "fail", "skipped"]
    summary:    str                # one line, user-facing
    evidence:   dict               # typed payload, node-specific

class SatQueryState(TypedDict):
    query:      str
    images:     list[ImageManifest]
    validation: list[CheckResult]
    task:       TaskClassification | None
    plan:       ExecutionPlan | None
    outputs:    dict[str, ToolOutput]
    answer:     Answer | None
    confidence: ConfidenceBreakdown | None
    trace:      Annotated[list[TraceEntry], operator.add]   # ← reducer
AcceptanceEvery completed run exports a JSON trace that replays the decision path with no reference to model reasoning text. Two runs on identical inputs produce identical plan sections.
OR-2

Stream the trace to the UI as it builds

Nodes emit over SSE as they complete, so the evaluator watches validation pass, the task get classified, candidates get filtered, and models execute — live, before the answer appears. This is the demo moment. A trace revealed only after the answer reads as post-hoc justification; a trace that builds in front of the judge reads as an agent working.

AcceptanceFirst trace entry renders in the UI within 500 ms of submit, well before the final answer.
CF-1

Confidence is a named breakdown

Report components, each in [0,1], with the aggregate and the weakest link surfaced: input quality (co-registration score, cloud/nodata fraction, GSD match), task classification (classifier top-1 margin), model fitness (declared eval score of the selected model on the nearest matching benchmark), and output agreement (whether the VLM's claim is corroborated by the specialist — e.g. VLM says "water present", fusion encoder's water logit).

Output agreement is the component that makes this credible rather than decorative, and it is cheap: you already run both models.

AcceptanceA query where the VLM and the specialist disagree returns a visibly reduced confidence and names the disagreement in the trace.
06

Geospatial input handling

Verdict

pip install rasterio now ships Windows wheels with GDAL bundled (Python ≥ 3.10) — the old conda-only advice is stale. Use pip wheels for speed; keep a conda-forge environment documented as the fallback, since the wheels omit some optional GDAL drivers. Do not install standalone GDAL.

Stack: rasterio for I/O, CRS, transforms, and windowed reads · pyproj for CRS comparison and coordinate transforms · shapely for footprint intersection · numpy for band math. That is the whole dependency set. Add rio-cogeo only if you want COG validation as a nice-to-have trace line.

VR-1

Validation check suite

Each check is a named function returning CheckResult(name, status, expected, actual, message). Status is PASS, WARN, or FATAL. Only FATAL halts.

Per image

  • readable — opens via rasterio; driver recorded FATAL
  • format_allowed — GeoTIFF/TIFF always; PNG/JPEG accepted only when the run is flagged as benchmark mode FATAL
  • has_crs — src.crs is not None; absent means not georeferenced WARN
  • has_transform — affine is not the identity default WARN
  • band_count_sane — 1–13; recorded for modality inference WARN
  • nodata_fraction — fraction of nodata/zero pixels; >40% degrades confidence WARN
  • dimensions — flags oversized scenes that must route through tiling WARN

Per pair

  • crs_match — identical CRS, or reprojectable; mismatched but reprojectable is a WARN with the transform logged
  • footprint_overlap — intersection.area / min(area_a, area_b); ≥ 0.80 required to claim co-registration FATAL below 0.30
  • gsd_ratio — src.res comparison; ratio outside [0.5, 2.0] means one must be resampled, recorded explicitly
  • grid_alignment — origin offset modulo pixel size; sub-pixel residual is the real test of co-registration, and it is what distinguishes "same area" from "same grid"
  • modality_distinct — for cross-modal tasks, the two images must infer to different modalities
  • temporal_order — reads acquisition date from TIFF tags where present; orders the pair, warns if unavailable
AcceptanceA deliberately mismatched pair (different CRS, 60% overlap, 4× GSD difference) produces three specific named WARNs and a reduced confidence — not a crash and not a silent success.
VR-2

Modality inference from pixels, not filenames

Infer from band count, dtype, and value distribution; use filename and TIFF tags only as a corroborating hint, and log both the inference and the hint.

  • SAR — 1–2 bands, float32, very wide dynamic range, strongly right-skewed histogram (linear backscatter), or already in dB with negative values
  • Optical RGB — 3 bands, uint8
  • Optical multispectral — 4–13 bands, uint16
AcceptanceCorrect modality on all Bhoonidhi fixtures and on BigEarthNet S1/S2 patches, with filenames stripped.
VR-3

SAR preprocessing — the quality cliff

This is where teams lose the cross-modal requirement without noticing. A naive min–max stretch on SAR backscatter produces a near-black image, because a handful of bright scatterers dominate the range. Feed that to a VLM and it describes an empty scene, confidently.

Required pipeline: linear → dB (10·log10, guarding zeros) → clip to the 2nd/98th percentile → scale to 8-bit → replicate to 3 channels. For dual-pol, VV/VH/ratio is a more informative false-colour composite than a grey replication, and it costs one line.

AcceptanceSide-by-side visual check on a real EOS-04 scene: the naive stretch and the dB-percentile stretch are both rendered in the fixture notebook, with the difference documented. The VLM produces a non-degenerate description on the latter.
07

Ranked risks and pre-validation

Ordered by expected damage at hour 30 of 36 — probability of occurrence multiplied by how much of the deliverable it takes down. Every entry has an action that can be completed now, before the finale.

1

Environment collapse on Windows

Remote-sensing VLM repos pin old transformers versions and assume flash-attn, which does not build cleanly on Windows. Two model repos with conflicting pins in one environment is a multi-hour hole with no partial credit.

Pre-validate Build and freeze the full inference environment inside WSL2 or Docker today. Run one real query through each candidate model. Export the exact lockfile. Choosing the 3B Qwen path largely dissolves this — it runs on stock transformers with no custom fork.

Critical
2

Hidden ISRO set breaks the ingest path

Every benchmark is a small tile; the hidden set is real Cartosat-2S and RISAT scenes with unfamiliar band ordering, dtype, nodata convention, and scene size. A pipeline that only ever saw 512² PNGs fails on the one input that counts.

Pre-validate Register on Bhoonidhi, pull real Cartosat-2S and EOS-04 GeoTIFFs, and make them permanent test fixtures. Build the tiling path early — you will be handed a scene, not a patch.

Critical
3

Cross-modal fusion ends up cosmetic

The requirement most likely to be technically unmet while appearing met. Running an optical model and a SAR model separately and concatenating their text is not extracting complementary information, and a domain judge will ask exactly that question.

Pre-validate Ship AR-1's fused encoder with the three-way ablation (S2-only / S1-only / fused). A single table where fused beats both is the entire defence, and it comes free with the run you were already doing.

Critical
4

SECOND download unavailable

CDVQA imagery depends on one Google Drive link with no license and no mirror. If it is quota-limited during the finale, the mandatory change-analysis evaluation has no data.

Pre-validate Download and mirror today (DR-1). Verify filename cross-match against the CDVQA JSONs before assuming they align.

High
5

Fine-tune produces no measurable gain

A LoRA run that trains cleanly but does not beat the base model leaves requirement #1 defensible only on paper.

Pre-validate Track A is the insurance and is near-certain to work — supervised multi-label classification with a labelled dataset is well-trodden. Fix the eval subset and score the base model before training, so you can measure a delta rather than hope for one.

High
6

VRAM exhaustion mid-demo

Two 7B models plus specialists will not co-reside on 16 GB. Load/unload swapping adds 15–30 s per query — fatal for a live demo.

Pre-validate Commit to the MR-1 single-VLM budget now and measure peak VRAM on the heaviest query type. This is an architecture decision, not a tuning problem — deciding it late means rewriting the registry.

High
7

Frontend consumes the last eight hours

The natural failure mode for a backend-strong team: the agent works, and the demo cannot show it.

Pre-validate Build the React shell — upload, query box, streaming trace panel, image overlay canvas — before the finale, against a mocked SSE stream. The trace viewer is the only bespoke component that carries evaluation weight; everything else can be an unstyled component library.

High
8

Weight downloads inside the venue

Tens of GB of checkpoints over contested hackathon wifi, at the worst possible moment.

Pre-validate Pre-cache every checkpoint to local disk and carry it physically. Set HF_HUB_OFFLINE=1 and confirm the system boots with networking disabled.

Medium
9

Change-VQA accuracy is poor

CDVQA answers span six land-cover classes with counting and comparison question types; a weak change mask propagates into every answer.

Pre-validate Score the compositional path on CDVQA's test split early. If the mask is the bottleneck, the fix is a better CD head — a bounded, well-understood problem — not a better prompt.

Medium
10

Live demo failure

Any of the above, on stage, in front of judges.

Pre-validate Build a fixture mode that replays saved traces at realistic speed against known-good inputs, plus a recorded walkthrough. Demo from fixtures; offer live as the encore.

Medium

09

Open questions

  • Cartosat-2S band configuration in the hidden set. Panchromatic only, or MX four-band? This changes what the optical branch receives and whether the fused encoder's 10-band S2 stem needs a projection layer. Resolve empirically from Bhoonidhi fixtures.
  • RISAT/EOS-04 product level. Whether the SAR arrives as calibrated backscatter or raw DN determines whether VR-3's dB conversion is correct or double-applied. Read the product metadata rather than assuming.
  • EarthDial SAR checkpoint. The paper claims SAR in its instruction mix, but only RGB, MS, and Methane/UHI checkpoints appear to be released. If a SAR checkpoint exists, it is a strong shortcut for requirement #4 and worth an hour to confirm.
  • Trace format expectations. The PS mandates an auditable trace but does not specify a schema. Ship JSON with a rendered human view and state the schema explicitly in the README.
  • Scene-scale queries. If a query concerns a full scene rather than a tile, aggregation across tiles is an unspecified design decision. Simplest defensible answer: tile, run per-tile, aggregate with counts and spatial extents, and record the tiling in the trace.
